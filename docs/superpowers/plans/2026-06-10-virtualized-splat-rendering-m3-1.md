# Virtualized Splat Rendering — M3.1 (Turning the 16.6 ms Gate Green) Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use **superpowers:subagent-driven-development** (recommended) or **superpowers:executing-plans** to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

> **EXECUTION:** the engine lane is free — no external workflow gates. The ONLY gate is internal ordering: **Task 1 (instrumentation) completes before any optimization task starts**, and Tasks 2→5 each record their before/after stage-table numbers so every optimization is chosen and judged from data, not guessed. Run in the main repo on `blitz/day1-foundation`.

**Goal:** Take M3's honestly-red gate (10k buildings p50 67.9 ms, 1k buildings p50 37.6 ms, both at the governor-railed 100k budget) to green — p50 ≤ 16.6 ms on the AMD 780M — by first MEASURING where the frame goes (per-stage table), then removing the four code-verified fixed overheads: per-frame 192–312 MB entry-scratch alloc/free churn, a per-frame compute-pipeline creation, a redundant 59 MB/frame texture zero-fill, and two of the four per-frame blocking GPU syncs (the select readbacks, fused to one).
**Done When:** On the AMD 780M (RADV), all three of:

2. `cargo run --release -p vox_app --bin scale_trial -- --instanced --buildings 1000` (the 26M-tile-entry worst case) **exits 0** with its own printed lines, **p50 ≤ 16.6** and `entry_overflow max=0`.
3. The M3 contract suites stay bit-green untouched: `cargo test -p vox_render --lib instanced_gpu_ -- --nocapture` prints `[instanced_gpu] draws bit-equal across 9 (camera,budget) combos`, the fallback and determinism lines; `cargo test -p vox_render --lib instanced_selector` 5/5; `cargo test -p vox_render --test tiled_splat_renderer_test` 2/2.

This is the dev-floor gate on the 780M; numbers on other machines are recorded manually later, never gated here.

**Architecture:** Instrumentation-first, then four levers ordered by code-verified evidence size. (1) A per-stage GPU/host timing table (timestamp queries on the two select kernels we own — the harness device already requests `TIMESTAMP_QUERY`, `scale_trial.rs:355` — host spans everywhere the frozen chain's own compute passes forbid pass-boundary timestamps). (2) Persistent tile-assign entry buffers + a constructed-once `write_indirect_args` pipeline (today: 3 × `max_tile_entries × 4 B` buffers AND a full shader-module→pipeline build EVERY frame, `tile_assign.rs:152–168` / `:249–323`). (3) Drop the per-frame 4-layer output zero-fill (59 MB/frame of `queue.write_texture` staging at 720p, `tiled_splat_renderer.rs:869–899`) — provably redundant because `splat_raster.wgsl:124–135` unconditionally stores layers 0/1/3 for every in-bounds pixel every frame. (4) Fuse the GPU select into ONE submit + ONE readback by moving near-pair emission GPU-side with a deterministic serial prefix scan and an indirect kernel-2 dispatch — the host budget walk STAYS (the one-walk-two-scorers bit-equality contract with the CPU selector is the proof mechanism; a fully GPU-side walk feeding expand without host round trip would break that contract AND `ExpandDrawsPass::encode`'s host draw-list input, so it is the named escalation, not this plan). (5) Prepared (persistent) bind groups/params for the radix/range/raster encodes. The frozen four-pass WGSL chain is untouched; all changes to its Rust wrappers are additive methods with the old entry points byte-stable.
**Design Document:** `docs/superpowers/specs/2026-06-10-virtualized-splat-rendering-design.md` (§2 M3, §4.6–4.8; §8 anticipated "port more to GPU" as the escalation — M3.1 ports the pair *emission*, not the walk)
**Tech Stack:** Rust (workspace, edition 2024), wgpu 24, glam 0.29, bytemuck 1, half 2 (vox_render). `vox_app` has **no bytemuck**; PNG via the zero-dep `vox_app::shell::cpu_render::write_png`.
**Build:** `cargo build` / targeted `cargo test -p vox_render --lib <filter>` only. **Never run the full `vox_render --lib` suite as a gate** (the pre-existing `resident_gi_seam` flake — radix raster nondeterminism); use the filters named per task.

- **Where the ~31 ms "rest" goes — code-verified evidence (Task 1 attributes it precisely; Tasks 2–5 remove it):**
  1. **Entry-scratch alloc/free churn:** `TileAssignPass::dispatch` (`gpu/tile_assign.rs:152–168`) creates 3 buffers of `max_tile_entries × 4 B` EVERY call, sized from the CAPACITY-derived `max_tile_entries` — 16M entries at the 1M cap ⇒ **192 MB/frame**; after the 1k-run's in-frame growth to ~25.9M entries ⇒ **~311 MB/frame**. wgpu zero-initializes buffers on first use; the previous frame's set is dropped when `assign` is reassigned next frame and destroyed inside the NEXT `poll(Wait)` — which is the select's `map_read` poll (`gpu/instanced_select_gpu.rs:696`) — so the churn is **misattributed to select_ms**. This is the leading suspect for BOTH the inflated select (43 ms) and the rest.
  2. **Per-frame pipeline creation:** `dispatch_write_indirect_args` (`gpu/tile_assign.rs:249–323`) builds a shader module + BGL + pipeline layout + compute pipeline EVERY frame (×2 on a grow-retry frame) — naga parse/validate + RADV pipeline create on the hot path.
  3. **59 MB/frame texture zero-fill:** `render()` (`gpu/tiled_splat_renderer.rs:869–899`) does 4 × `queue.write_texture` of a 14.7 MB zero row at 1280×720 — redundant: `splat_raster.wgsl:124–135` unconditionally `textureStore`s layers 0/1/3 for every in-bounds pixel, the raster dispatch covers the full tile grid every frame (`splat_raster.rs` `dispatch_workgroups(num_tiles_x, num_tiles_y)`), `tile_range_build` clears all `num_tiles` ranges each frame, and layer 2 is written by no pass and read by no path (`resolve_to_srgb` reads layers 0–1 only).
  4. **Four blocking submit→poll syncs/frame, zero overlap:** select k1 (`instanced_select_gpu.rs:550–551`), select k2 (`:609–610`), the count readback (`tiled_splat_renderer.rs:802–806`), encoder B (`:971–972`). Task 4 removes one; the count readback and encoder-B poll stay (the chain's contract).
  5. **Encoder-B host churn:** `radix_sort_pass.rs:315–371` — 8 × (fresh `create_buffer_init` params staging + fresh bind group) per frame; `tile_range_build.rs:152–170` and `splat_raster.rs:177–223` — fresh params buffer + bind group (+ a texture view) per frame.
  6. **The irreducible GPU work** (radix 8 passes × histogram+scatter over the REAL entry count `n`, plus the EWA raster) scales with entries — once 1–5 are gone, the `FrameBudgetGovernor` (already wired, 14.5 ms setpoint) finds the budget that fits; no governor change is planned.
