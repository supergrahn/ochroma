# World-Scale NYC — M1 Ingestion Spike (Lower Manhattan Tile) Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use **superpowers:subagent-driven-development** (recommended) or **superpowers:executing-plans** to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One real Lower-Manhattan tile in the running game: pinned NYC open-data snapshot (deterministic, cached), real 1-ft-DEM terrain through forge's existing-but-dead `load_dem_png`, and ~1,000 real building footprints placed under the architecture decision **footprints drive INSTANCES, not assets**: bucket by shape class × footprint-size bucket × height bucket (~25–40 buckets expected for this low-rise bbox), ONE hand-tunable archetype directive per bucket, a placements file mapping every footprint to (archetype id, position, rotation, fit-scale within a pinned tolerance, real Address/BIN as per-instance metadata), instances placed through the existing registry/placement path picking up `InstanceVariation` for free (skyscraper/odd lots keep the honest imposter-box placeholder treatment), and an inspector that shows the clicked building's **real address and BIN from instance metadata, never from the asset**.
**Done When:** On the 780M, all of:
1. `cd ~/Ochroma/projects/civitas_care && cargo run --release --bin nyc_fetch` prints one line per snapshot item ending `OK (downloaded) sha256=<12-hex>` or `OK (cached) sha256=<12-hex>` plus a license line per source, exit 0 — and a **second run prints `OK (cached)` for every item with the same hashes** (deterministic snapshot).
2. `cargo run --release --bin nyc_directives` prints `[nyc-gen] footprints=<~1000> low_rise=<n> placeholders=<p> (tall=<t> odd_footprint=<o> odd_fit=<f> missing_data=<m>) buckets=<b>` with `b` in the expected 25–40 band (hard assert `b ≤ 48`), **the actual per-bucket histogram (this print IS an acceptance artifact — paste it into the task report)**, `[nyc-gen] fit-scale: p95 per-axis within [0.80, 1.25] (max=<s>)`, `[nyc-gen] instance/asset ratio = <n>/<b> ≈ <r>:1`, and `[nyc-gen] projection check: median |area_proj-area_attr|/area_attr = <e>% (n=<k>)` with `e < 1.0` — every number real.
3. `cargo run --release --bin game_asset_cook` prints a `cooked nyc.<bucket-id> …` line for every bucket (and each sparing variant) and writes them into `pack.json` (no cook-binary edits — directives only); the cooked-payload count tracks **buckets, never placements** (~30-ish payloads ≈ ~100 MB / minutes, not ~1,000 ≈ 2 GB+ / an hour+).
4. `cargo run --release --bin nyc_tile_import` prints `[nyc-import] dem <W>x<H> @ 2.0 m | elev min=<a> m max=<b> m | dem-vs-groundelev median |Δ|=<d> m (n=<k>) | water_bodies=<≥2> | buildable=<pct>% | wrote civitas_data/maps/nyc_lower_manhattan_m1` with `b − a` in (2.0, 60.0) and `d < 1.5`.
5. `cargo run --release --bin play -- --nyc-shot nyc_m1_inspector.png` writes the PNG and prints `inspector title: Building — <name>` plus lines including `Address      <real PLUTO address>`, `BIN          1<6 digits>`, and `latlon       40.7…, -74.0…  (Δ <2.0> m vs snapshot)` with the printed Δ `< 2.0` — and a human can reach the same inspector through the menu: New Game → map `NYC — Lower Manhattan M1` → Start Game → Inspect tool → click a building.
**Architecture:** Everything is game-layer (`civitas_care`); engine and Forge are consumed, not edited. **Footprints drive INSTANCES, not assets** — the cooked-asset count is bounded by buckets (~25–40), never by footprints (~1,000). Pipeline: `nyc_fetch` (curl house pattern → pinned snapshot + manifest) → `nyc_directives` (EPSG:2263 projection + OBB fit → bucket by shape class × footprint-size × height → ONE archetype `.asset.json` per bucket, kept if hand-tuned + `placements.json` mapping every footprint to archetype id/position/rotation/fit-scale/Address/BIN) → `game_asset_cook` (unchanged, discovers directives) → `nyc_tile_import` (forge `load_dem_png` + sidecar datum → `import_real` → map dir) → `play` (placements → `LotPlan`s → `place_real_city` develops instantly through the existing registry path, `InstanceVariation` off `seed = BIN` → inspector side-table shows Address/BIN **from per-instance metadata**).
**Design Document:** `docs/superpowers/specs/2026-06-10-world-scale-nyc-design.md`
**Tech Stack:** Rust (workspace toolchains as-is), system `curl` via `std::process::Command` (the `polyhaven_fetch.rs` pattern), `tiff` crate (new civitas dep, GeoTIFF decode), `image` 0.25 (already a dep — PNG16), serde_json. **No wgpu/Slang work; no SPECTRA env.**
**Build:** `cd ~/Ochroma/projects/civitas_care && cargo test` (targeted filters) / `cargo run --release --bin <bin>`. Civitas links `vox_render` via path dep — see the build gate below.

- **Bucketing pin (Task 3) — footprints drive INSTANCES, not assets:** low-rise/cookable = rectangularity ≥ 0.78 AND OBB ≤ 30×30 m AND floors ≤ 6. Bucket key = **shape class × footprint-size bucket × height bucket**: shape class from OBB aspect `max(w,d)/min(w,d)` — `sq` ≤ 1.3, `ob` ≤ 2.2, `dp` > 2.2 (M1 cooks Rectangular only; L/U/T/odd → placeholder); footprint-size = OBB-area bands `{≤80, ≤150, ≤300, ≤600, ≤900 m²}`; height = floors bands `{1-2},{3-4},{5-6}` — 45 possible cookable buckets, **expected occupied: 25–40 for this low-rise bbox** (a count < 10 means the bucketing collapsed — bug); hard assert `b ≤ 48` (cook-cost ceiling). **ONE archetype directive per occupied bucket, hand-tunable:** the generator writes a directive only when the file is absent (prints `kept (hand-tuned): <id>` otherwise; `--force-directives` overwrites); intra-bucket variety = the existing `variants` merge patches (sparing — **each variant is its own cooked ~1.5–3.5 MB payload**) + the shipped `InstanceVariation` (mirror/yaw/setback/tint/anti-CGA scale, pure function of `lot.seed = BIN` — `render_gpu/mod.rs`, zero edits needed). Directive `forge.width/depth` = bucket median OBB; `floors` = band; `kind`/siding/palette from the bucket's **majority** zone-class + `bldgclass` first letter (A→Clapboard house, B/C/D→Brick rowhouse, else Stucco); `seed` = FNV of bucket id (deterministic). Placements carry the real per-footprint zone; if `lot_asset` refuses a pinned asset over a zone mismatch, split that bucket on zone-class and report — never edit the registry. **Fit-scale pin:** per placement, per-axis `footprint OBB dim / archetype dim`, pinned tolerance **[0.80, 1.25]**; out-of-tolerance → reassign to the neighboring size bucket, else placeholder reason `OddFit` (counted). Fit-scale is **recorded in placements.json but NOT applied at render time in M1** — render_gpu is locked (`InstanceFrame.scale` is the one-line application point, owned by living-instances Task 6 / M2); the tolerance bounds the visible footprint mismatch at ≤ 25%. Everything else (tall, odd, missing) → placeholder with reason, **counted and printed, never dropped silently** — placeholders keep the honest imposter-box treatment (the existing procedural fallback massing, `asset_id: None`), and their inspector still shows real Address/BIN from instance metadata.
- **Cost arithmetic (why instances, not assets — the decision this plan encodes):** cooked atom payloads measure **~1.5–3.5 MB each** (`assets/buildings/forge_starter/atoms/*.atoms.json`, 2026-06-10 cook). ~30 archetype buckets ⇒ **~30 cooked assets ≈ ~100 MB of payloads, minutes of cook**. Per-footprint directives at ~1,000 ⇒ **~1,000 cooked assets ≈ 2–3.5 GB, an hour+ of cook** — and it destroys the dedup architecture every engine budget depends on: the splat atom library (~70 KB+/unique asset, "≤ a few hundred unique assets ≈ tens of MB resident" — virtualized design §4) and the SDF atlas (200 unique assets ≈ 36 MB measured vs per-instance 1.8 GB "impossible" — SDF pillar design §4.1) both **scale with UNIQUE assets, never with instances**. The atom library / SDF atlas dedup is preserved by construction: instance count is free, unique-asset count is the budget.
- **Construction fast-forward pin (Task 6):** `place_real_city` develops every lot at `now_tick = self.tick_index`, then runs `self.instances.tick(&mut self.sim.buildings, &self.placed_lots, &demand, t)` for `t = tick_index+1 ..= tick_index+build_ticks(max_level)+1` — registry ticks only flip construction → Active and engine `operational` (pure, no economy side effects; verified `tick` body). M1 save/replay of real-city games is OUT (no authored action; the tile reloads fresh each run — printed honestly at load: `[nyc] real-city tile: M1 spike, save/replay lands in M2`).
- `todo!()` / `unimplemented!()` / empty function bodies are **forbidden** — they fail the task. Every test asserts a real computed value and prints it.
