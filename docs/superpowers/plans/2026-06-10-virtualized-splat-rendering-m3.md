**Goal:** Make `scale_trial --instanced` hold 60 fps at 10,000 buildings on the AMD 780M by (1) self-healing the tile-entry capacity bug that dropped 9.86M tile entries in the 1,000-building low orbit, (2) porting the instance+cluster *scoring* of `InstancedSelector` to GPU compute on the shared context (the proven `AtomBudgetGpu` doctrine: parallel scoring on device, the tiny sequential budget walk on host — measured CPU select is 19.56 ms of the 72.46 ms frame), and (3) closing the loop with a frame-budget governor that holds the measured frame time at a 14.5 ms setpoint by modulating the atom budget.
**Done When:** On the AMD 780M (RADV), all three of:
1. `cd ~/src/ochroma && cargo run --release -p vox_app --bin scale_trial -- --instanced --buildings 10000` prints `[scale_trial] instanced: 10000 buildings | library_atoms=<L> virtual_atoms=50000000 | budget=<B> selected=<S> | select+expand+render p50=<X> ms p99=<Y> ms @ 1280x720` with **X ≤ 16.6** (asserted in-binary, exit 0), a detail line `select_ms p50=<s> | gpu_fallbacks=0 | entry_overflow max=0 | budget_settled=<B<1000000> ema_ms=<E> | non_black=<nb>/921600 (<pct≥25.0>%)`, and writes `scale_trial_instanced.png` (a human opens it and sees a city grid of distinct buildings).
2. `cargo run --release -p vox_app --bin scale_trial -- --instanced --buildings 1000` (the measured worst case: low orbit, dense screen coverage, the run that overflowed 9,857,730 entries pre-M3) exits 0 with its own printed line, **p50 ≤ 16.6** and `entry_overflow max=0`.
3. `cargo test -p vox_render --lib instanced_gpu_ -- --nocapture` prints `[instanced_gpu] draws bit-equal across 9 (camera,budget) combos` and `[instanced_gpu] city-scale select: cpu_ms=<c> gpu_ms=<g>` with `g < c`, plus the M1 suite still bit-green: `cargo test -p vox_render --lib instanced_selector` (the budget-walk extraction must not change one bit of CPU behavior).

This is the dev-floor gate on the 780M; numbers on other machines (tomespensin) are recorded manually later, never gated here.

**Architecture:** Three levers, smallest risk first. (a) `TiledSplatRenderer::render` already reads back the true tile-entry demand each frame — when a capacity-constructed renderer overflows, grow the entry scratch (3 persistent sort tmps; the 3 per-frame `tile_assign` buffers size themselves from `max_tile_entries` automatically) and re-run the idempotent `tile_assign` in the same frame, clamped at device limits. (b) `InstancedSelectGpu` — a shared-context twin of `InstancedSelector` that scores instances (kernel 1: classify cull/far/near + far score) and near-instance clusters (kernel 2: per-(instance,cluster) frustum/LOD/score) on the GPU with the exact `atom_budget_gpu.wgsl` op order, reads back two small score arrays, and feeds the EXTRACTED (`pub(crate)`, behavior-identical) host budget walk — output draws bit-equal to the CPU selector, which stays as the oracle and the deterministic fallback. (c) `FrameBudgetGovernor` (design §4.7 verbatim: `budget ← clamp(budget·(target/ema)^0.5, min, max)`) wraps the per-frame budget in the harness, fed the honest full-loop wall ms (`raster_gpu_ms` is hard-coded `None` on this chain). The frozen four-pass WGSL chain is untouched.
**Design Document:** `docs/superpowers/specs/2026-06-10-virtualized-splat-rendering-design.md` (§2 M3, §4.6–4.8)
**Tech Stack:** Rust (workspace, edition 2024), wgpu 24, glam 0.29, bytemuck 1, half 2 (vox_render). `vox_app` has **no bytemuck**; its PNG writer is the zero-dep `vox_app::shell::cpu_render::write_png`.
**Build:** `cargo build` / targeted `cargo test -p vox_render --lib <filter>` only. GPU tests are plain wgpu — no SPECTRA env, no Slang. **Never run the full `vox_render --lib` suite as a gate** — it has one pre-existing flake (`resident_gi_seam`, radix_sort raster nondeterminism); use the filters named in each task.
